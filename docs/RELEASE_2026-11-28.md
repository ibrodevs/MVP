The first Production candidate returned 503 for availability. Sanitized runtime logs identified Google STS rejection by the provider attribute condition, followed by an IAM impersonation 403 after the condition was corrected. No raw OAuth token or upstream credential body was logged.

With explicit customer confirmation, the provider condition was saved as:

```cel
assertion.owner == 'ibroits-projects' && assertion.project == 'mvp' && assertion.environment in ['preview', 'production']
```

Issuer/audience and owner/project restrictions were preserved. The owner then added the exact Production subject under roles/iam.workloadIdentityUser on bte-booking@bte-global-booking-516005.iam.gserviceaccount.com in Cloud Shell. Successful policy output showed both Preview and Production subjects. After permission propagation, Production FreeBusy and availability returned HTTP 200 with 17 one-hour slots for 30 November. No service-account key, broad pool grant or Calendar sharing change was needed.
