## Исправления

1. GET config не обращается к PostgreSQL. Успешный ответ имеет 30-секундный CDN-кэш; отдельный ограничитель 120/min/IP, ограниченная память, опциональные атомарные Redis REST-счётчики. Без Redis/WAF лимит действует на экземпляр, не глобально на deployment. Ошибки Redis при его настройке закрывают доступ с 503.
2. Добавлен paid_pending_calendar. Только успешное создание/восстановление Calendar event переводит бронь в confirmed. Миграция 002 обновляет ограничения и старые преждевременно подтверждённые записи без event ID. Пока событие не создано, оплаченный интервал остаётся занят.
3. Worker блокирует и outbox, и booking. Получатели одного заказа сериализованы, разные заказы исполняются параллельно. notification_sent_at заполняется один раз только при наличии обеих завершённых email-задач. Внешние вызовы ограничены общим 40-секундным deadline; SQL-ошибки откатывают транзакцию.
4. Сборка публикует только 24 разрешённых клиентских файла в public/. Серверный код, миграции, документация, тесты и env-файлы не являются статическим output. /api собираются Vercel отдельно. Добавлен .vercelignore.
5. Preview mock учитывает VERCEL_ENV, а не только NODE_ENV. NODE_ENV=production в Preview допустим; Production и неизвестные Vercel targets запрещают mock. Production endpoint отклоняется до обращения к БД. Origin берётся из APP_BASE_URL либо доверенных Vercel URL, а не из произвольного Host.

## Оставшиеся внешние условия

Полный cloud checkout требует отдельных Preview DATABASE_URL и mock-настроек из DEPLOYMENT.md. Настройки production и доступы к нему не изменялись. Для реальных сервисов нужны Google Calendar/SMTP credentials, утверждённый график, юридические согласования, мониторинг и будущая Ziina-интеграция.

SMTP не даёт строгой exactly-once гарантии при аварии после приёма письма и до commit; стабильный Message-ID и блокировки защищают от обычной повторной/конкурентной обработки, но не отменяют эту границу протокола. Google FreeBusy+insert также не атомарны относительно посторонних писателей календаря. Эти ограничения сохранены в документации без обещаний, которые код не может гарантировать.
